# Nexora Core — پروکسی تلگرام و تحریم‌شکن

لیست زنده‌ی پروکسی‌های MTProto تلگرام، با جستجو، فیلتر نوع (FakeTLS / Secure / ساده)، علاقه‌مندی، کپی لینک، QR و دکمه‌ی «اتصال در تلگرام».
منبع لیست: [SoliSpirit/mtproto](https://github.com/SoliSpirit/mtproto) (بروزرسانی هر ۱۲ ساعت). سایت هر ۳۰ دقیقه لیست را دوباره می‌گیرد.

سایت فقط یک صفحه‌ی HTML ثابت است و به هیچ سرور یا برنامه‌ای نیاز ندارد.

## «اضافه شده» و جلوگیری از تکرار
- با زدن «اتصال در تلگرام» کارت علامت **اضافه شده ✓** می‌گیرد و دکمه دیگر دوباره لینک را باز نمی‌کند. (دکمه‌ی ↺ علامت را برمی‌دارد، اگر پروکسی را از تلگرام پاک کردید.)
- علامت‌ها در مرورگر ذخیره می‌شوند و فیلتر «اضافه‌شده» دارند. «اتصال تصادفی» پروکسی‌های اضافه‌شده را رد می‌کند.
- لیست هم تکراری ندارد: یک پروکسی با secret یکسان در فرمت‌های مختلف (hex، حروف بزرگ/کوچک، base64) فقط یک‌بار نشان داده می‌شود.

## وضعیت و پینگ
سایت پینگ نشان نمی‌دهد (مرورگر نمی‌تواند به پورت پروکسی وصل شود). بعد از افزودن پروکسی، خود تلگرام وضعیت و پینگ را با اینترنت شما در بخش Proxy نشان می‌دهد.

## بالا آوردن روی GitHub Pages
1. در GitHub یک مخزن عمومی بسازید، مثلاً `tg-proxy`.
2. همه‌ی فایل‌های این پوشه را در ریشه‌ی مخزن آپلود کنید.
3. `Settings → Pages` → Source: **Deploy from a branch** → Branch: `main` و پوشه‌ی `/ (root)` → Save.
4. بعد از چند دقیقه سایت روی `https://USERNAME.github.io/REPO/` باز می‌شود.

## «جدید» و «پایدارترین» (بر اساس تاریخچه‌ی لیست)
یک GitHub Action (`.github/workflows/update.yml`) هر ۳۰ دقیقه لیست منبع را می‌گیرد و در `seen.json` ثبت می‌کند هر پروکسی از کی در لیست بوده. سایت همین فایل را می‌خواند و روی کارت‌ها «جدید» (کمتر از ۶ ساعت) و «مدت حضور در لیست» را نشان می‌دهد؛ مرتب‌سازی «جدیدترین» و «پایدارترین» هم همین‌جا کار می‌کند.
- راه‌اندازی: `Settings → Actions → General → Workflow permissions` را روی **Read and write** بگذارید، بعد در تب Actions یک‌بار `update-seen` را با **Run workflow** اجرا کنید.
- اجرای اول فقط مبنا را می‌سازد (چیزی «جدید» نمی‌شود) و مدت حضور آن پروکسی‌ها به‌صورت «حداقل …» نوشته می‌شود.
- اگر `seen.json` نبود، سایت مثل قبل و بدون این برچسب‌ها کار می‌کند.


## ساختار صفحه‌ها

## تحریم‌شکن (V2Ray)
یک GitHub Action دیگر (`.github/workflows/update-v2ray.yml`) هر ۳۰ دقیقه این دو منبع عمومی را می‌گیرد:
[ZendanTeam/SS44-sub](https://github.com/ZendanTeam/SS44-sub) و [drmikecrypto/PulseConfigs](https://github.com/drmikecrypto/PulseConfigs).
بعد از پاک‌سازی، دو فایل می‌سازد: `sub.txt` (لینک اشتراک برای برنامه‌ها) و `configs.json` (لیست سایت).

**فیلترها:** خطوط خراب، تکراری‌ها (بین هر دو منبع)، کانفیگ بدون رمزنگاری، تأیید گواهی خاموش (`allowInsecure`)، Shadowsocks با رمزنگاری قدیمی یا رمز عمومی، آی‌پی‌های خصوصی، و سرورهایی که پورتشان در تست TCP بسته بود.
بعد با اولویت Reality ← TLS ← بقیه مرتب می‌شود (حداکثر ۱۲۰ کانفیگ، ۶۰ تا از هر پروتکل).
**نام‌گذاری:** هر کانفیگ نام `Nexora Core | VLESS Reality | a3f9` می‌گیرد (کد کوتاه ثابت است) و اشتراک عنوان «Nexora Core | کانفیگ رایگان» و آدرس سایت را در هدر دارد.
فایل‌ها فقط وقتی کامیت می‌شوند که لیست واقعاً عوض شده باشد.

- راه‌اندازی: فایل `update-v2ray.yml` را در مسیر `.github/workflows/` بسازید و در تب Actions یک‌بار **Run workflow** را بزنید. (نیازی به تنظیم اضافه نیست؛ دسترسی نوشتن داخل خود فایل است.)
- **محدودیت:** تست پورت از سرور GitHub انجام می‌شود، نه از ایران. «پورت باز» یعنی سرور روشن است، نه اینکه حتماً وصل می‌شود.
- این کانفیگ‌ها عمومی و بررسی‌نشده‌اند؛ سرورها مال ما نیستند و در سایت به همین صراحت نوشته شده.
- اگر منابع در دسترس نباشند یا کمتر از ۸ سرور باز مانده باشد، فایل‌های قبلی دست‌نخورده می‌مانند.
- **پینگ:** ربات پینگ TCP هر سرور را از سرور GitHub می‌گیرد، گرد می‌کند و در `configs.json` (فیلد `ms`) می‌گذارد. تا وقتی تغییر بزرگ نشده همان مقدار قبلی می‌ماند تا کامیت اضافه نخورد. روی کارت‌ها با رنگ نشان داده می‌شود و مرتب‌سازی «کمترین پینگ» دارد.
- **v2rayNG:** در اندروید کارت‌ها دکمه‌ی «افزودن به v2rayNG» دارند (لینک `v2rayng://install-config?url=`) و کارت اشتراک `v2rayng://install-sub?url=`.
